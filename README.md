# Team Flow

Team Flow 是 Orca 的中文队伍侧栏：配置一名主脑和多名协作成员，输入目标，先了解项目并确认计划，再按边界自动推进实现、验证、审核和有限返工。可查看真实任务状态、成员输出和主脑汇总；沿用 Orca 的原生编排，不另外运行一套调度引擎。

默认使用 Claude Code 做主脑、Codex 做实现、OpenCode 做审核。可以添加更多实现成员，也可以定义前端、后端、测试、文档、排查、安全审核等角色。同一个 Agent 可以配置给多名成员，每名成员有独立任务和会话，并可分别指定模型及受支持的思考强度。主脑在 CLI 终端中运行；协作成员由 Orca 原生 worker 启动，遵循该 Agent 的 Chat／CLI 偏好，不能一概视为直接调用 CLI。账号仍沿用 Orca 的现有配置。

## 从保存队伍到执行当前项目

1. **在 Orca 打开要修改的本机项目。** 核对侧栏「当前项目」中的项目名称和完整路径。执行目标是这个项目，不是插件安装目录；远程项目、路径不可确认时不能启动。
2. **打开「队伍设置」。** 选择主脑 Agent，通过「添加成员」增添角色，为每名成员填写名称、Agent、模式和职责。主脑和每名成员的模型都可直接从下拉列表选择，不必记模型 ID；选择「沿用 Agent 默认」则不覆盖模型。选定具体模型后，可按该模型及 Agent 的能力分别设置思考强度。至少保留一名实现和一名审核，最多 16 名协作成员，不含主脑。
3. **点击「保存队伍」。** 保存只记录配置，不会启动智能体、读取项目或修改代码。已有运行仍保留启动时的队伍，修改配置只影响下一次启动；未保存编辑时不能启动，需先保存或取消。
4. **设置当前工作区的任务。** 在「工作区长期说明」保留项目目标、开发约束和长期验证要求；在「任务需求」与「验收标准」描述本次具体改动和可检查结果。三项均按 Orca 工作区自动保存，切换后恢复对应内容，关闭面板后仍可恢复，不必每次重写。每项最多 4000 字。验收标准可以留空，此时主脑先提出验证方式，涉及关键取舍时询问用户。
5. **设置「执行边界」，再点击「启动队伍」。** 允许修改的路径为项目相对字面路径，每行一条，默认 `.`；默认不允许项目联网、依赖安装和文件删除，最多自动返工 2 轮。后台重新核对当前项目与模型／强度能力，保存完整启动快照；主脑此时仅只读了解项目，不应启动实现成员或修改文件。配置或启动回执不代表执行完成。
6. **阅读「运行流程」中的计划。** 核对步骤、预计修改路径、验证方式和风险；点击「确认计划并执行」才发送该版本授权。需要调整时填写反馈并「要求修改计划」，重新提交的计划必须再次确认。修改下一次任务的边界草稿不会改变当前运行。
7. **查看自动推进和真实结果。** 主脑在已批准范围内安排实现、验证、审核及有限返工，范围内常规工作不应反复询问。每名成员有独立状态与输出入口；「查看主脑汇总」读取真实会话，有终端的成员可打开终端处理权限或输入。完成应列明实际改动、验收结果、执行过的验证、审核发现和未解决事项。

例如：需求填写「设置页保存空名称时应阻止提交，并显示明确错误」；验收填写「空名称不能保存；合法名称保存成功；相关验证通过」。不要仅输入「帮我完成整个项目」而没有目标或范围。

## 模型、思考强度与实际启动

- **角色名称、Agent、模型和思考强度是四项不同配置。** 例如「后端实现」是成员角色，Agent 是执行它的程序，模型 ID 与思考强度分别是该 Agent 的启动选项。同一个 Agent 的不同成员可以指定不同模型和不同强度。
- **可以统一 harness，而不是统一会话。** 多个角色可选同一个 Agent，分别设置模型和强度；是否支持某厂商／模型，以该 harness 的实际目录、启动能力及账号权限为准，不能任意跨 CLI 套用模型 ID。角色的职责、上下文和读写边界仍分别定义。
- **按角色成本档位做路由（不是失败重试）。** 每名成员可标记「成本档位」：贵审判（规划、审核、验收、关键取舍）只做判断；便宜打工承担大体量、机械或已明确的执行。主脑按难度和档位派工：简单活优先便宜成员，复杂难点或最终裁决给贵成员；不会为花掉预算把简单活分给贵模型，也不会为省钱让便宜成员独自做高风险修改。返工沿用原成员参数，不自动换更贵模型；确需换更强成员时按新 Task 显式派发并说明原因。档位是路由提示，不代表运行时能力已核实。
- **默认队伍不锁模型，只锁分工。** 主脑本身是贵审判；默认成员为「实现（便宜打工）＋审核（贵审判）」，档位默认只影响派工倾向，模型仍可自由选择和更换。旧配置迁移后沿用同一套默认档位，可再自行改档或换模型。
- **优先用模型下拉列表。** 打开队伍设置时，面板按 Agent 自动读取目录；更换 Agent 会读取对应列表，多个同款 Agent 的成员仍可各选不同模型。需要更新列表时可重新读取；原有模型即使暂时不在目录中也会保留，不会擅自替换成第一个选项。只有选择高级自定义选项时才需手填模型 ID／选择器。
- **目录来源明确显示。** Codex 使用独立的 `codex debug models`，失败时仅使用真实存在的本机模型缓存并标明降级；OpenCode 使用 `opencode models --pure`；OMP 使用 `omp models --json --no-extensions`，保留其原生 `selector`。查询不会创建对话、提交任务或发送推理请求；CLI 可能按自身规则更新目录缓存或刷新认证。
- **Claude 提供官方别名预设。** 可直接选择 Sonnet、Opus、Haiku，具体版本由 Claude 映射；它们不是本机账号权限验证，也不伪装成从当前账户读取的精确版本列表。
- 目录属于当前工作区下的本机 CLI 环境，不保证与 Orca 托管账号或 Chat 模式完全相同，也不证明实时权限、额度或服务可用性。OpenCode／OMP 为查询禁用外部插件／扩展加载，插件独有模型可在高级选项保留。不支持显式模型参数的 Agent 仍只能使用默认值。
- 原生下拉框有选项数限制；目录过大时提供按模型名称筛选，不截断后端目录。读取失败会说明原因，可重读或沿用已保存模型；不会编造模型或静默改选。默认模型的具体值和运行时实际生效值仍不冒充已核实。
- 当前启动契约支持 Claude、Codex、Cursor、Antigravity、Grok、Muse、OMP、Pi 和 OpenCode 的显式模型参数。OpenCode 仍要求宿主确认 CLI 与模型可用，Pi 使用 `provider/id` 格式。不支持显式选择的 Agent 只能沿用自己的配置；切换 Agent 时需重新设置模型，避免串用上一个 Agent 的模型。
- 主脑的模型与强度直接传给 `agent launch --model <ID> --effort <档位>`；成员的指定值写入主脑编排清单中各自的 `startupArgs`，由主脑执行 `worker-start` 时传入，不是插件另建调度器强制注入。未指定的参数不传；不可用或被拒绝时应报告阻塞或失败，不允许主脑擅自删掉参数改用默认重试。复用已有终端时继承原会话的模型和强度，不能通过复用参数切换。
- 队伍预览和运行卡显示的是**配置的模型／选择器与思考强度**，不是服务端的实测回执；选择默认时明确显示具体值未知。模型、供应商和组织策略可能限制或调整实际强度，不能以配置冒充实测。编辑队伍不会更换已启动会话的参数。

### 思考强度如何选择

- 先选择具体模型。当前 Orca 的 `--effort` 必须与 `--model` 一起使用；「沿用默认」不等于中档，也不等于关闭思考。更换 Agent 或模型会清除该角色原来的强度，提示重新选择；刷新目录不会擅自改选或清除已保存值。
- **Codex** 的档位来自每个模型的 `supported_reasoning_levels`；保留目录实际返回的新档位，不统一写死为低／中／高。目录的 `default_reasoning_level` 只是目录建议，不是本机配置或运行时默认的实测值。
- **OMP** 的档位来自每个模型的 `thinking` 列表；明确不支持推理的模型不能指定强度。保留完整 provider／selector，不把不同提供商的同名模型混为一项。
- **Claude／Pi** 可提供文档或 CLI 契约中的档位预设；预设不是本机能力探测，也不保证所有模型、版本或供应商都支持。目录已明确给出档位时以该模型目录为准。**OpenCode** 当前没有 Orca 的显式 effort 路径，不能把底层 CLI 的 variant 冒充成已接通的启动配置；其他未确认支持的 Agent 只能沿用默认。
- 对支持 effort 但目录缺少具体档位的模型，保留明确标注的高级原始档位输入，由用户填写已确认的 CLI 档位，启动时仍可能被宿主或模型拒绝；不编造通用档位。已保存但不再被目录支持的值会保留并显示校验问题，需重新选择或主动清空后再启动。

## 计划确认、自动推进与边界

- **计划有版本。** 规划阶段提交结构化摘要、步骤、预计修改路径、验收验证及风险。确认精确绑定工作区、运行及计划版本；旧计划、旧工作区的确认不能放行新计划。批准前不会发送执行指令，确认按钮不把成员状态伪装成已运行或已完成。
- **授权后少打断，但有终点。** 允许范围内按实现→验证→审核推进；实现成员在同一工作区保持串行，只读分析可按依赖并行。最多返工次数为初次实现之外的完整返工轮次，按整个 Run 累计；耗尽、越界、高风险、权限阻塞、关键歧义或持续失败时记录阻塞并等待人工，不无限新启。
- **路径与操作分开设置。** 最多 32 条项目相对路径，不支持 glob；拒绝遍历、绝对路径及常见 Windows 路径别名绕过。项目联网、依赖安装、删除各自显式允许，且仍限已批准计划。Git 提交／推送／合并、发布、生产操作、秘密文件、全局配置及权限绕过始终不自动执行。
- **送达不明不重发。** 授权先持久化再通过原生邮件发送给原主脑；并发点击不会重复发送。超时、丢失回执或发送中重启后保持待人工核实，先打开主脑检查。发送受理不证明主脑已经开始，更不证明任务完成；完成仍由原生任务、实际验证和审核确认。
- **不是通用权限沙箱。** 路径校验限制计划声明，角色与返工规则交由主脑及原生任务协作执行；不隔离文件系统、符号链接或任意 shell 命令，也不关闭各 CLI 自己的权限保护。面板确认属于正常工作流，不是不可伪造的人类授权证明：Orca 开发桥接可模拟面板请求，同用户本机进程也不是独立安全边界。不能据此运行不可信模型／脚本并声称其无法越权。
- 当前采用本文的**本地开发加载**方式；主脑用 `orca plugin dev request local.team-flow` 提交计划与阻塞报告。没有把仅开发模式可用的桥接宣称为正式发布插件的通用 API。旧运行没有工作流字段时继续按原生历史状态显示，不伪造已批准计划。

## 工作区绑定与持续开发

- 「工作区长期说明」「任务需求」「验收标准」与「执行边界」绑定当前 Orca 工作区；项目 A 与项目 B 各自保留，不共享任务草稿。没有有效本机工作区时不能启动。
- 启动后保留已填写内容，便于持续开发时复用或修改；「清空本次任务」仅清空任务需求和验收标准，不删除长期说明，也不取消正在运行的任务。
- 长期说明会附在每次**手动启动**的任务中。修改说明只影响下一次启动，不会给正在运行的队伍追加指令；保存、切换项目、重新打开面板均不会自动启动或重复执行任务。
- 队伍配置仍可跨项目复用；运行记录仍是每个工作区最近一次运行。切换项目会退出未保存的队伍编辑并清除输出选择，旧工作区的晚到回执不能写进新工作区。

## 成员模式与协作边界

| 模式 | 适合角色 | 执行规则 |
| --- | --- | --- |
| 实现 | 前端、后端、编写测试、维护文档 | 可以修改项目；同一工作区按实现成员的列表顺序串行执行，后一个依赖前一个 |
| 分析 | 问题排查、需求分析、测试策划 | 只读调查；没有数据依赖时可并行 |
| 审核 | 代码审核、安全审核、验收 | 只读检查，依赖本次全部实现任务成功完成 |

角色名称和职责可以自定义；需要编写测试文件或文档的角色也应选择「实现」，而不是「分析」。这些是主脑提示词与原生任务依赖的协作要求，**不是技术沙箱或独立文件权限**。本版本不支持多名成员在同一目录中并行写入，不自动提交、推送或合并。

队伍配置保存在本机，可用于不同项目；每个工作区保留最近一次运行。旧版固定分工配置会保留原 CLI 并转换为成员列表，旧运行仍按原任务前缀读取。成员采用稳定标识关联任务，改角色名不会串到其他成员；返工任务和多次派发按当前任务及宿主最新派发记录显示，关联不唯一时明确提示未知。

## 状态异常时

- 未确认旧队伍结束、启动或需求送达回执不明确时，不允许再次启动，避免重复执行；先查看主脑及成员会话。
- 同步异常或状态未知时会继续尝试刷新，也可点击右上角刷新按钮。最近成功同步时间与任务完成状态分开显示。
- 运行卡住、主脑失联或需提前收口时，在「运行流程」卡右上点「结束本次运行」；二次确认（可填原因）后把本次运行标记为已结束并释放「启动队伍」，不可恢复，未完成的成员任务不会自动续跑。
- 已结束的终端不一定保留可读取输出；读取失败会说明原因，可在主脑会话查看原生任务结果。不会把缺失输出包装成成功结果。
- 切换项目会恢复对应工作区的任务与长期说明，同时退出未保存的队伍编辑、清除输出选择，并阻止旧工作区请求影响新项目。

## 本地加载

需要 Orca 1.4.268 或更高版本。在插件目录执行以下命令，并在 Orca 查看和批准插件权限，再打开右侧栏 **Team Flow**。

```powershell
orca plugin dev load . --json
orca plugin open local.team-flow --panel team-flow --json
```

## 开发验证

```powershell
orca plugin types . --json
npm ci
npm run typecheck
orca plugin test . --json
orca plugin check . --json
```

`src/protocol.ts` 定义队伍、运行、计划与请求协议，以及旧配置迁移与校验。`src/workflow.ts` 校验边界及计划；`src/model-catalog.ts` 仅读取并投影模型目录元数据；`src/flow.ts` 生成规划／执行指令、关联成员任务和当前派发。`src/worker.ts` 负责 CLI、存储、版本确认、防重复送达与保守的原生状态核实。`src/panel.tsx` 提供项目指引、成员编辑、任务边界、计划确认与输出入口。

回归用例覆盖配置迁移、多实现成员、模型／强度独立选择、工作区持久化、路径与计划校验、计划版本确认、并发点击防重复发送、未知送达及重启恢复、返工关联、原生完成状态和旧回执隔离。面板检查包含规划、计划待确认、未知送达、边界草稿、模型／强度及长期说明场景。模拟测试不替代真实多 Agent／多模型协作验证；开发检查不会启动真实队伍。

测试套件通过各工作区的独立持久化种子、卸载后重开以及晚到回调验证数据隔离；`TestPanel.emit` 不会模拟宿主对工作区状态的重新加载，不能把它当作真实 A→B→A 切换验证。真实切换时的工作区状态重载由 Orca 宿主负责。
